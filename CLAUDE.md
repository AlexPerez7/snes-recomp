# snes-recomp

Recompilador estático de ROMs de SNES (CPU 65816) escrito en Rust desde cero. Este repositorio es el **motor** (público, MIT) y no incrusta ningún juego: cada juego es un perfil `games/<id>.toml` (+ `games/<id>/*.c`) en su propio repositorio. Primer juego: *The Legend of Zelda: A Link to the Past* (USA, CRC32 `777AAC2F`), en el repositorio hermano `alttp-recomp` (`..\alttp-recomp` en esta máquina). Ambos son públicos: https://github.com/AlexPerez7/snes-recomp y https://github.com/AlexPerez7/alttp-recomp; antes de cada push, `scan` de lo que se sube.

## Comandos

```
cargo test                                          # tests unitarios; sin juego real se omiten los que lo necesitan
$env:SNES_GAME_PROFILE="..\alttp-recomp\games\alttp_usa.toml"; $env:SNES_GAME_ROM="roms\alttp_usa.sfc"; cargo test   # también las pruebas con el juego real (se omiten si el CRC32 de la ROM no es el del perfil)
cargo run --release -- scan roms/alttp_usa.sfc <carpeta>   # falla nombrando el fichero si algo de la carpeta lleva bytes de la ROM; úsalo antes de publicar
cargo run --release --bin snes-port -- roms/alttp_usa.sfc [--cache D] [--no-launch] [--fast] [--download-compiler] [--game PERFIL.toml]... [-- OPCIONES_DEL_JUEGO]   # construye el juego desde la ROM del usuario (caché <crc32>-<versión>) y lo arranca; `snes-port clean [rom]` borra la caché
powershell -File scripts\release.ps1   # out\release\snes-port-<v>-win64.zip; falla si hay .sfc/.smc/.srm o C generado
cargo run --release -- info roms/alttp_usa.sfc      # cabecera, CRC y vectores
cargo run --release -- disasm roms/alttp_usa.sfc 00:8000 40
cargo run --release -- discover roms/alttp_usa.sfc  # añade --unresolved para ver saltos indirectos sin tabla, o --widths para ver conflictos M/X, PLP sin emparejar y llamadas sin retorno
cargo run --release -- graph roms/alttp_usa.sfc [00:8000]  # resumen, o detalle de la función que contiene la dirección
cargo run --release -- codegen roms/alttp_usa.sfc 00:8000 --depth 1 -o out/reset.c  # C de una función y sus llamadas
cargo run --release -- codegen roms/alttp_usa.sfc --all -o out/rom        # C de toda la ROM: rom_BB.c por banco, snes_funcs.h y snes_rt.h; las funciones no traducibles quedan como stub (rt_unsupported) y se listan
# Ejecutar la ROM completa sin vídeo ni audio (con Visual Studio: desde "x64 Native Tools" o tras vcvars64.bat):
#   cl /MP /TC /std:c11 /DSNES_RT_TICK /DSNES_RT_CHECKS /Iout\rom out\rom\*.c out\rom\game\*.c /Fe:out\headless.exe /Fo:out\rom\   (game\*.c solo si el perfil tiene C propio; `codegen --all` lo escribe)
#   out\headless.exe roms\alttp_usa.sfc --frames 120 [--frame-blocks 20000] [--dump out\dump] [--screenshot out\shot.png]   # informe de registros, DMA y causa de parada; --game-opt CLAVE=NUMERO (repetible; opciones del C del juego, p. ej. dialog_skip=0 desactiva la mejora de mensajes de ALttP; también en snes_play.exe), --wide N (múltiplo de 8 hasta 96; ensancha N columnas por lado la imagen de --screenshot, que muestra lo que dibuja la PPU fuera de los 256 de la consola: los fondos continúan por su mapa), --poke ADDR=BYTES@N (bytes en hex; mismas direcciones que --watch) escribe en WRAM al empezar el fotograma N, p. ej. --poke 20=5008@10400 mueve a Link; --dump (carpeta existente) escribe vram.bin, cgram.bin, oam.bin, ppu_regs.bin y wram.bin (128 KiB; Link está en $20 Y, $22 X, $8A área); --screenshot dibuja el estado final de la PPU (modos 0 a 6 con BG4 y offset por tile, sprites y color math con color fijo o subpantalla; HDMA reproducido línea a línea, ventanas (BG1-3, sprites y ventana de color), mosaico de los fondos y modo 7 (matriz, centro y scroll, también por HDMA)) en un PNG de 256x224
#   Mando 1: --press BOTONES@A-B (repetible; B Y SELECT START UP DOWN LEFT RIGHT A X L R unidos con +; fotogramas A a B desde 0) simula lectura automática ($4218-$4219 con $4200 bit 0) y serie ($4016); p. ej. --press START@1100-1110 lleva ALttP a PLAYER SELECT
#   Trazas (compilar además con /DSNES_RT_TRACE): --trace-frames A-B abre la ventana de fotogramas (desde 0); dentro de ella, --trace-reads imprime las lecturas de $2100-$43FF con el bloque que las hace y --watch ADDR (repetible: 0000-1FFF, 7E:xxxx, 7F:xxxx u offset de 17 bits) los cambios de ese byte de WRAM
#   out\headless.exe roms\alttp_usa.sfc --frames 100 --trace-frames 90-91 --trace-reads --watch 11
#   Audio: --wav out\title.wav escribe el audio de la ejecución (SPC700 + DSP reales; PCM 16 bits estéreo a 32 kHz); 1200 fotogramas son ~20 s
# Jugar con ventana, teclado/mando, sonido y partidas guardadas (necesita el paquete de desarrollo SDL2 para Visual C++, SDL2-devel-x.y.z-VC.zip, descomprimido en out\sdl2 o apuntado por SDL2_DIR):
#   cd out\rom ; set SDL2_DIR=...\SDL2-2.30.9 ; build_play.bat   # compila snes_play.exe y copia SDL2.dll (codegen --all escribe build_play.bat y play\snes_play.c)
#   snes_play.exe ..\..\roms\alttp_usa.sfc [--scale 3] [--fullscreen] [--mute] [--wav F.wav] [--stats]
#   Sin ROM (doble clic o sin argumentos) abre el diálogo de Windows para elegirla.
#   Opciones: config.ini junto a la ROM (se crea con los valores por defecto, conserva comentarios y claves desconocidas; ver la tabla del README). La línea de comandos manda solo en esa ejecución: --scale N, --fullscreen, --opt CLAVE=VALOR (repetible; claves: fullscreen vsync aspect scale scaling filter overscan wide scanlines grid fps volume; wide=N, múltiplo de 8 hasta 96, ensancha la imagen N píxeles por lado). F1 abre el menú (imagen, audio, controles de los jugadores 1 y 2); se guarda al cerrarlo. <rom>.keys solo se importa si aún no hay config.ini.
#   Pruebas del menú y la imagen sin ventana: snes_play.exe <rom> --no-window --frames 40 --menu-keys F1,Down,Down,Down,Down,Right,Escape --print-config (teclas de SDL, una por fotograma desde el 3; Q/W cambian de pestaña, Esc cierra y guarda), --menu-shot F.png --menu-page N (menú dibujado sobre el último fotograma; N = pestaña: 0 Image, 1 Audio, 2 Controls, 3 Game; imprime un hash FNV del dibujo), --present-shot F.png --present-size WxH (la imagen como la presenta la ventana, con el renderizador por software)
#   Teclas: flechas, X=B, Z=Y, S=A, A=X, Q=L, W=R, Intro=START, Mayús dcha=SELECT; F11 pantalla completa, P pausa, Tab acelera, F10 captura PNG, Esc sale. F1 menú (pestañas Image, Audio, Controls, Game; Q/W cambian de pestaña). --print-keys lista el teclado del jugador 1. Cualquier mando SDL (hot-plug) también juega: el primero es el jugador 1 y el segundo el 2.
#   La SRAM se guarda en <rom>.srm junto a la ROM (cada ~1 s si cambia y al salir) y se recarga al arrancar.
#   Sin ventana (tests): snes_play.exe <rom> --no-window --frames N [--hold BOTONES] [--press BOTONES@A-B] [--screenshot F.png] [--wav F.wav]
```

## Estructura

- `src/rom.rs`: carga de ROM, mapeo LoROM, cabecera y vectores.
- `src/opcodes.rs`, `src/disasm.rs`: tabla de opcodes y decodificador, con seguimiento de los anchos M/X.
- `src/discover.rs`: descubrimiento de código por descenso recursivo, guiado por la configuración. Sigue los anchos M/X por contexto de función (entrada, anchos), a través de llamadas, retornos y pares `PHP`/`PLP`.
- `src/graph.rs`: bloques básicos y funciones a partir del descubrimiento (aristas, tail calls, diagnósticos).
- `src/codegen.rs`: generador de C (una función por función del grafo, una etiqueta por bloque) y pruebas que compilan y ejecutan el C. Un bloque alcanzado con anchos M/X distintos que cambian su C se emite una vez por combinación de anchos (`Discovery::transitions`, etiquetas `L_BB_AAAA_m8x16`, y un prólogo que elige la copia por `c->m`/`c->xf` si la función se llama con varios); solo queda como stub si un inmediato cambia de longitud con los anchos. `generate_all` emite todas las funciones y deja las que no puede traducir como stub. Los retornos no locales (descartar una dirección con `PLA`/`PLA` antes de `RTS`) funcionan porque `RTS`/`RTL` dejan la dirección en `Cpu.ret` y cada llamada comprueba `S` y `ret` al volver; si ninguna llamada acepta el retorno, el runtime sin vídeo para con `rt_lost_return` (salida 14).
- `runtime/snes_rt.h`: interfaz del C generado con el runtime (estado de la CPU, bus, ganchos, aritmética). Se incrusta en el binario.
- `runtime/snes_core.inc`, `runtime/snes_ppu.inc`, `runtime/headless.c`: el runtime sin vídeo se reparte en el núcleo de hardware (`snes_core.inc`: bus, registros, DMA, reloj, contextos, informe), la PPU (`snes_ppu.inc`: dibujador y PNG, incluido por el núcleo) y el frontal sin vídeo (`headless.c`: opciones y `main`). Los `.inc` no se compilan solos: los incluye `headless.c` (`codegen --all` los escribe junto a `snes_headless.c`, y el glob `out\rom\*.c` solo compila los `.c`). Lo que sigue describe el conjunto.
- `runtime/snes_spc.inc`: el lado del sonido, incluido por el núcleo: SPC700 completa (RAM de 64 KiB, ROM de arranque de 64 bytes, puertos `$F4-$F7`, tres temporizadores) y DSP (8 voces BRR con ADSR/GAIN, ruido, modulación de pitch, eco con FIR). Corre con el reloj de fotogramas (17039 ciclos de SPC700 por fotograma) y genera una muestra estéreo cada 32 ciclos hacia `audio_hook`. La interpolación usa un núcleo en forma de campana, no la tabla gaussiana exacta del hardware. Tests en `src/spctest.rs`.
- `runtime/play.c`: frontal interactivo con SDL2 (ventana con aspecto, escalado, filtros, overscan y efectos, menú F1, ritmo de 60,0988 Hz, teclado y mandos de dos jugadores, audio por cola de SDL con el vídeo mandando y volumen maestro, SRAM en `.srm`, `--no-window` para tests); `codegen --all` lo escribe como `play/snes_play.c` junto a `play/play_cfg.h`, `play/play_ui.h` y `build_play.bat`.
- `runtime/play_ui.h`: el aspecto del menú sin SDL: fuente de píxeles propia proporcional (formas 5x7 engrosadas, con sombra, medida y recorte con «...»), panel con marco, regla, barra, cursor y flechas, todo sobre un `Canvas` RGB que recorta; sus tests compilan el `.h` solo con bytes de guarda (`src/headless.rs`). Ni la fuente ni los adornos vienen de la ROM.
- `runtime/play_cfg.h`: la parte de `play.c` que no necesita SDL (tabla de opciones, INI que conserva claves desconocidas, rectángulo de la imagen, efectos, volumen, asignación de teclas); sus tests compilan el `.h` solo (`src/headless.rs`).
- `runtime/headless.c` (conjunto): runtime sin vídeo (bus LoROM, registros que guardan lo escrito, DMA real, VRAM/CGRAM/OAM con volcado `--dump`, `--wav` con el audio, bus LoROM, registros que guardan lo escrito, DMA real, VRAM/CGRAM/OAM con volcado `--dump`, captura `--screenshot` del modo 1, los sprites y el color math, trazas `--trace-frames`/`--trace-reads`/`--watch`, latch de contadores H/V (`$2137`, `$213C/$213D`, `$213F`), IRQ vertical (`$4200` bits 4-5, `$4209/$420A`, `$4211`), contextos de ejecución (fibras; un `RTI` con otra `S` cambia de contexto, como hace la intro de ALttP entre NMI e IRQ), fotogramas por bloques, NMI, informe). `codegen --all` lo escribe como `snes_headless.c`, junto a `snes_entry.c`; la ROM se lee del disco, nunca se incrusta. Tests en `src/headless.rs`.
- `src/cctest.rs`: solo para tests; busca `CC`/gcc/clang/cc o Visual Studio y compila C.
- `src/port.rs`, `src/toolchain.rs`, `src/download.rs`: el constructor `snes-port` (segundo binario, el mismo `main.rs`; arranca como `port` si se llama así). `port.rs`: caché atómica (`<crc32>-<versión>`, directorio temporal + marca `.complete`), versión = CRC32 de runtime, configuraciones y generador, compilación (MSVC por `vcvars64.bat`, gcc/clang, TinyCC) y la comprobación de que ningún byte de la ROM acaba en lo construido. `toolchain.rs`: detección del compilador. `download.rs`: única red del programa (TinyCC con SHA-256 fijado, solo sin compilador local y con consentimiento); `network_requests()` lo comprueban los tests. `SNES_TCC_EXE` activa el test de construcción con TinyCC; `cargo test -- --ignored the_real_tinycc` prueba la descarga real.
- `src/config.rs`: formato de los perfiles `games/<id>.toml` (documentado al inicio del fichero): entradas, tablas, `[game]` (id, nombre, CRC32) y `[[hook]]`.
- `src/games.rs`: perfiles de juego (un `.toml` con `[game]` más la carpeta hermana `games/<id>/` con su C propio). `Catalog::discover` reúne los de `games/` del directorio actual y junto al ejecutable (`search_dirs()`; el actual manda) y los de `--game` (que mandan sobre todos); un `.toml` roto en una carpeta se avisa y se omite; mismo CRC32 dos veces en un sitio es error. El motor no trae ninguno.
- El perfil de A Link to the Past (`games/alttp_usa.toml`, `games/alttp_usa/dialog.c`) vive en el repositorio `alttp-recomp`, con su `scripts/check.ps1` (prueba de los mensajes con R) y su `release.ps1`. El C propio de un juego es código original y puede distribuirse; no deriva de la ROM. Las pruebas del motor que necesitan un juego real usan `cctest::real_game()` (`SNES_GAME_PROFILE`, `SNES_GAME_ROM`).
- Ganchos (`Emitter::with_hooks` en `src/codegen.rs`): `before`/`after`/`replace` sobre la entrada de una función; con ganchos el cuerpo pasa a `static f_XX_YYYY_body` y la función pública es un envoltorio. El C del juego usa `snes_rt.h` (`wram_read8/wram_write8`, `joy1_state()`, `game_opt()`, `ppu_sprite_xoff(i, dx)`/`ppu_sprite_xoff_clear()` para poner un sprite en las columnas extra de la derecha de un campo ancho, `ppu_wide()` para leer el ensanche E vigente, `ppu_wide_blank(izq, der)`/`ppu_wide_blank_clear()` para dibujar en negro esa cantidad de píxeles de las columnas extra de cada lado); `snes-port` lo copia a `game/` y lo compila con el resto, y la versión de la caché lo incluye.

## Reglas

- El código es propio (clean-room): no copiar código de otros recompiladores.
- El ROM lo aporta el usuario. Nunca se sube ni se distribuye: `roms/` y `*.sfc`/`*.smc` están en `.gitignore`.
- Las tablas de saltos que se añadan a un perfil (`games/*.toml` de un repositorio de juego) se comprueban a mano contra el ROM real.
- El C generado deriva del ROM: va a `out/` (ignorado) y nunca se sube.
- Los tests que necesitan compilador o el ROM se omiten solos si faltan; en esta máquina se usa Visual Studio Build Tools.
- Los cambios se hacen con OpenSpec: `/opsx:explore`, `/opsx:propose`, `/opsx:apply`, `/opsx:archive`. Contexto del proyecto en `openspec/config.yaml`.
- Artefactos de OpenSpec y documentación, en español.
